# v0.2 Part B — Workspace Tabs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several projects or workspaces can be open at once, one per tab. Each tab keeps its own session, watcher, journal, conflicts and filters. Work in a background tab keeps running. Tabs are restored on the next launch.

**Architecture:**
- **Live state vs snapshots.** The store keeps its existing flat fields (`session`, `detected`, `version`, `conflicts`, `sourceMissing`, `recovery`, `error`) as the live state of the **active** tab. Every other tab is kept as a snapshot in `tabs[]`. Switching tabs swaps the two, so every existing component and test that reads `useApp.getState().session` keeps working unchanged.
- **Per-tab resources.** Watcher, journal timer, subscription and deferred sync move from module globals into a `Map<tabId, TabRuntime>`.
- **Addressing a tab.** Background callbacks update their own tab through `patchTab(id, partial)`. That writes to the flat fields when the tab is active, and to its snapshot otherwise.
- **Rendering.** Only the active tab's `AppShell` is mounted. Per-tab UI state (page, filter, hidden columns) lives in the tab. A "Translate missing" run moves out of the dialog into a small per-tab run store, so it outlives the dialog and the tab switch.

**Tech Stack:** React 19 + Zustand + Vitest/Testing Library (frontend), Rust/Tauri 2 (watcher, quit interception), `@tauri-apps/plugin-process` (`exit`).

**Spec:** `docs/superpowers/specs/2026-11-04-retrans-v0.2-additions-design.md`, Part B. Restore uses Part A's prefs. Spec Quality bar: "Tabs: independent sessions, background run continues, close/quit prompts, restore on launch".

**Builds on:** Part A, merged at `f28f3e4`.
- `src/platform/prefs.ts`: `getStore` runs `migratePrefs`; `PREFS_VERSION` is 2 in `src/platform/prefs-migrate.ts`.
- `src-tauri/src/lib.rs` already has a `.build(..).run(|app, event| ..)` callback that handles `RunEvent::ExitRequested`.

## Global Constraints

- Tab label: the project name plus a dot when it has unsaved changes. A background activity marker shows while a "Translate missing" run or a source sync is in flight in that tab.
- **Open project** and **Create new project** open a new tab, or switch to the tab already showing that folder (same `root`).
- Closing a tab with unsaved changes asks **Save / Don't save / Cancel**, the same prompt as closing a project today.
- Quitting asks **once**, listing every tab with unsaved changes. This covers the window close button, Cmd+Q / the app menu's Quit, and installing an update.
- Restore remembers the open tabs and the active tab. A tab whose folder is gone, or that can't be detected, is skipped with a notice: `Couldn't reopen <name>: the folder is gone.`
- One watcher per open tab. No limit on the number of tabs.
- No new npm or Rust dependencies. `@tauri-apps/plugin-process` is already installed; add the capability `process:allow-exit`.
- Prefs keys `openTabs: string[]` (roots, in tab order) and `activeTab: string | null`. **Don't** bump `PREFS_VERSION`: these are new optional keys, so a missing key reads as `[]` / `null`, and Part A's runner keeps unknown keys.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Before each commit: `pnpm test`, `pnpm exec tsc --noEmit`, and `cargo test` (when Rust changed).

## Review Focus

1. **A file changes on disk in a background tab with unsaved edits.** The reload and conflicts land in **that** tab's snapshot, never in the active tab. Switching to it shows the conflicts. Pinned by `background tab reload lands in its own snapshot` (Task 2).
2. **The same folder opened twice** (Recent list, then Open project, or the path with a trailing slash). It switches to the existing tab and never opens a second session on the same files. Pinned by `opening an open root switches to its tab` (Task 2), which also covers trailing slashes.
3. **Closing the active tab while a "Translate missing" run is going in it.** The run is cancelled and nothing writes to the closed session afterwards. Pinned by `closing a tab cancels its run` (Task 4).
4. **Restoring with a project whose base language can't be detected and was never saved.** The tab is skipped with a notice. Restore never blocks launch on a prompt. Pinned by `restore skips a project that needs a base-language pick` (Task 7).
5. **Quit with two dirty tabs, choosing Save, where one save fails** (conflicts, or a file is locked). The app stays open, that tab becomes active, and its error shows. Pinned by `quit stops at the first tab that fails to save` (Task 6).

- **Root identity:** `normRoot(root) = root.replace(/[\\/]+$/, "")`. Every root comparison and stored root uses it.

**Behaviour to implement:**
- **`openProject`:**
  - If a tab with the same normalized root exists, call `switchTab(id)` and return. That applies even when the call carries a `prebuilt` session: the prebuilt one is dropped.
  - Otherwise, snapshot the active tab, create a tab with `id = crypto.randomUUID()`, make it active, and run today's open logic, using a `TabRuntime` instead of the module globals.
  - The `openGen` staleness check becomes "is this tab still in `tabs`".
- **`TabRuntime`:** `{ journalTimer, journalFile, journalWrite, stopWatch, unsubscribe, deferredSync }`, held in a module-level `Map<string, TabRuntime>`. The existing helpers `scheduleJournal`, `dropJournal`, `teardown` and `runDeferredSync` take the runtime.
- **`get().session === session` checks:** every one in callbacks becomes `const id = get().tabIdOf(session); if (!id) return;` followed by `patchTab(id, …)`.
  - The session subscription bumps `version` through `patchTab`.
  - The journal schedule checks the tab still exists.
- **`closeProject()`:** tears down the **active** tab's runtime and removes the tab. It activates the tab to its right, else the one to its left, else sets `activeId = null`.
- **`switchTab`:** writes the flat fields (including `ui`) into the current tab's `snap`, loads the target's `snap` into the flat fields, and sets the target's `snap = null`.
- **`ui` default for a new tab:** `{ page: "translations", filter: INITIAL, hidden: [] }`. Move `INITIAL` (`src/ui/AppShell.tsx:24`) to a new `src/ui/tab-ui.ts` that exports `INITIAL_FILTER` and `defaultTabUi()`, and import the `Page`/`FilterState` types from there with `import type`, so the store never imports a component.
- **Unchanged API:** `save`, `requestClose`, `answerClosePrompt`, `resolveConflict`, `resolveAllConflicts`, `restoreRecovery`, `discardRecovery` and `syncSource` keep acting on the active tab. `syncSource` also wraps the sync in `markBusy(id, +1/-1)` for the session's tab.

### Task 6: Close and quit prompts

**Files:**

**Interfaces:**
- `closePrompt` gains a variant `{ then: "quit"; tabs: string[] }` (ids of the dirty tabs), and `"proceed"` gains `tabs: string[]`.
- **For one dirty tab,** the prompt looks exactly as it does today.
- **For two or more:**
  - title: `Save changes before quitting?`;
  - a list of the dirty tab names;
  - buttons: `Save all` / `Don't save` / `Cancel`.
- **`answerClosePrompt("save")` with `then: "quit"`:**
  - Saves each listed tab in order, activating it first.
  - It stops at the first `save()` that returns false: that tab stays active with its error, and the app doesn't quit.
  - Once all saves succeed, it quits.
- **`answerClosePrompt("discard")`:** drops every listed tab's journal, then quits.
- **Quit:** calls `exit(0)` from `@tauri-apps/plugin-process`. It does not call `destroy()`, so the Rust guard below sees an explicit exit code.
- **Single-tab close:** `requestClose("project")` and `closeTab(id)` keep the single-tab prompt for that one tab.
- **`confirmUnsaved()`** (update install) prompts for every dirty tab, using the same multi-tab prompt with `then: "proceed"`.
- **Window close button:** `useCloseGuard` → if any tab is dirty, `preventDefault()` and `requestClose("window")`. That now means "quit", with the list.
- **Cmd+Q / the app menu's Quit:**
  - Rust keeps `static UNSAVED: AtomicBool`, set by a new command `set_unsaved(on: bool)`.
  - The store calls that command whenever any tab's dirty state flips. Subscribe to the store and compare with the last value sent.
  - In the run callback, on `RunEvent::ExitRequested { code: None, api, .. }` with `UNSAVED` true: call `api.prevent_exit()` and emit `quit-requested` to the main window.
  - `App.tsx` listens for it and calls `requestClose("window")`.
  - Keep the existing `save_window_state` call.
