# v0.2 Part A — Settings Survive Quit, Update and Reinstall — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whatever the user configured stays as they left it after quit, auto-update or reinstall, including window size/position, with a versioned prefs file that later parts (B tabs, D providers) extend by migration.

**Architecture:** `prefs.json` (tauri-plugin-store, app data folder) gains a `prefsVersion` key and a small migration runner that runs once when the store is first loaded. It only ever adds or rewrites keys, never deletes, and leaves a newer-than-known file untouched. Window geometry is handled by the official `tauri-plugin-window-state`, which writes `.window-state.json` to the same folder. A Rust test pins the app identifier, which is the only thing the data-folder path depends on.

**Tech Stack:** TypeScript + Vitest (frontend), Rust (Tauri 2), `@tauri-apps/plugin-store` 2.5, `tauri-plugin-window-state` 2.x.

**Spec:** `docs/superpowers/specs/2026-11-04-retrans-v0.2-additions-design.md` (Part A; Quality bar → "Settings migration test")

**Scope note:** This is plan 1 of 4 (A → B → C → D), one per spec part. Two Part A rules are delivered by the parts that create their data. Open tabs and the active tab are stored by Part B through a migration added with this plan's runner. API keys in the OS credential store, including the Keychain-denied message, are delivered by Part D, which is the first code that has a key to store.

## Global Constraints

- The app identifier `com.retrans.app` must never change again (`src-tauri/tauri.conf.json` → `identifier`).
- All user state lives in the app data folder (`~/Library/Application Support/com.retrans.app/` on macOS, `%APPDATA%\com.retrans.app\` on Windows). Installers and the updater never touch it.
- Prefs are **migrated, never reset**. Unknown keys are kept, never dropped.
- A prefs file with no `prefsVersion` (every v0.1.0/v0.1.1 install) is version 1.
- No new npm dependencies. One new Rust dependency: `tauri-plugin-window-state = "2"` (never the 3.x alpha).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Before each commit: `pnpm test`, `pnpm exec tsc --noEmit`, and `cargo test` (in `src-tauri/`) all pass.

## Review Focus

1. **The user's real v0.1.x prefs file.** Everything in it must read back identically after the first v0.2 launch: recent projects, MT settings (enabled, model, accepted licences), per-project view modes, default view mode, update checks. Pinned by the fixture test in Task 1 (fixture copied from a real v0.1.0 install's key shape) and the manual real-file check in Task 3.
2. **The migration's own save fails** (disk full, read-only folder). The app must still open with the user's settings; the migration retries next launch. Pinned by `migration save failure does not block loading` in Task 1.
3. **A newer prefs file opened by an older app** (user downgrades). Nothing is rewritten and `prefsVersion` is not lowered. Pinned by `leaves a newer file untouched` in Task 1.
4. **Window restored off-screen** after unplugging a monitor. The window must open visible. The plugin clamps to an available monitor; checked manually in Task 2, step 5.
5. **Quit through the unsaved-changes prompt** (`getCurrentWindow().destroy()` in `src/ui/store.ts:402`) and **Cmd+Q**. The window geometry must still be saved on both paths. Checked manually in Task 2, step 5, with an explicit save on exit as the fallback.

**Interfaces:**
- Produces, for Parts B and D:
  - `export const PREFS_VERSION: number` (= `2` after this task).
  - `export interface PrefsKV { get<T>(key: string): Promise<T | undefined>; set(key: string, value: unknown): Promise<void> }`. The plugin-store `Store` satisfies it.
  - `export const MIGRATIONS: Record<number, (kv: PrefsKV) => Promise<void>>`. The entry at `n` upgrades version `n` to `n + 1`.
  - `export async function migratePrefs(kv: PrefsKV): Promise<"current" | "migrated" | "newer">`
  - **To add a migration in a later part:** add `MIGRATIONS[PREFS_VERSION]`, bump `PREFS_VERSION`, and add a `prefs-v<old>.json` fixture test like the v0.1.0 one.

- [ ] **Step 2: Write failing tests** in `src/platform/prefs-migrate.test.ts`. Use a Map-backed `PrefsKV` seeded from a plain object.

```ts
it("migrates a v0.1.0 prefs file without losing anything", async () => {
  const before = structuredClone(fixture);               // prefs-v0.1.0.json
  const kv = mapKV(fixture);
  expect(await migratePrefs(kv)).toBe("migrated");
  for (const [k, v] of Object.entries(before)) expect(await kv.get(k)).toEqual(v);
  expect(await kv.get("prefsVersion")).toBe(PREFS_VERSION);
});
it("is a no-op on a current file", async () => {
  const kv = mapKV({ ...fixture, prefsVersion: PREFS_VERSION });
  expect(await migratePrefs(kv)).toBe("current");
});
it("keeps keys it does not know", async () => {
  const kv = mapKV({ ...fixture, someFutureThing: { a: 1 } });
  await migratePrefs(kv);
  expect(await kv.get("someFutureThing")).toEqual({ a: 1 });
});
it("leaves a newer file untouched", async () => {
  const kv = mapKV({ ...fixture, prefsVersion: PREFS_VERSION + 5 });
  expect(await migratePrefs(kv)).toBe("newer");
  expect(await kv.get("prefsVersion")).toBe(PREFS_VERSION + 5);
  expect(kv.writes).toBe(0);                              // the helper counts set() calls
});
it.each([undefined, "2", -1, 1.5, null])("treats prefsVersion %p as version 1", async (v) => {
  const kv = mapKV({ ...fixture, prefsVersion: v });
  expect(await migratePrefs(kv)).toBe("migrated");
  expect(await kv.get("prefsVersion")).toBe(PREFS_VERSION);
});
it("runs each step in order from the stored version", async () => { /* spy on MIGRATIONS[1] and assert it ran once */ });
```

- [ ] **Step 4: Implement `src/platform/prefs-migrate.ts`**
  - `PREFS_VERSION = 2`.
  - `MIGRATIONS = { 1: async () => {} }`. v1 → v2 only adds the version stamp; later parts add real steps.
  - `migratePrefs`:
    - Read `prefsVersion`. Any value that is not an integer ≥ 1 counts as 1.
    - If the version is above `PREFS_VERSION`, return `"newer"` and write nothing.
    - If it equals `PREFS_VERSION`, return `"current"`.
    - Otherwise, run `MIGRATIONS[v]` for each `v` from the stored version up to `PREFS_VERSION - 1`, then set `prefsVersion` and return `"migrated"`.
    - Never call a delete.

- [ ] **Step 5: Run the tests and check they pass.** Same command. Expected: PASS.
