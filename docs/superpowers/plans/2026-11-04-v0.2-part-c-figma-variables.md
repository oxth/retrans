# v0.2 Part C — Figma Variables — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workspace can take Figma Variables exports (`.tokens.json`, one file per mode) as a second source next to TypeScript. Users translate those strings, give them code keys or link them to existing keys, resolve Figma-vs-code conflicts, and export `.tokens.json` files back to Figma with only `$value` changed.

**Architecture:**
- **Pure core in `src/figma/`:**
  - `tokens.ts` parses and rewrites DTCG files;
  - `sync.ts` does a three-way merge against a per-variable baseline;
  - `link.ts` suggests matches and links;
  - `export.ts` plans the Figma export.
- **Figma state lives in workspace meta** (`meta.figma`): folder, mode→language map, variableId→row links and the Figma baseline. It is saved with the workspace like everything else, with no new files to keep in step.
- **Rows:**
  - An unmapped Figma variable is a row in a Figma group (`figma-<collection>`), keyed by its Figma name.
  - Giving it a code key moves the row into a code group.
  - Linking points the variable at an existing row and drops the Figma row.
- **Store:** the existing sync, watcher and conflict machinery gains a `"figma"` origin.

**Tech Stack:** TypeScript, React 19, Zustand, Vitest/Testing Library. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-retrans-v0.2-additions-design.md`, Part C. Quality bar: "Figma: round trip … byte-identical; one edit changes only that `$value`; renamed-in-Figma variable keeps its links; linking and conflict flows; code export with and without code keys."

**Builds on (merged on `main`):**
- the tabs store (`src/ui/store.ts`): `syncSource(session)`, `patchSession`, `UiConflict`, the per-tab watcher in `openTab`;
- auto-save;
- the workspace sync (`src/workspace/sync.ts`), whose patterns this plan mirrors.

## Global Constraints

- **Format (checked against Figma's help, "Modes for variables", 2026-11-04):**
  - DTCG JSON, one file per mode;
  - the mode name is at root `$extensions["com.figma.modeName"]`;
  - each variable is `{ $type, $value, $extensions: { "com.figma.variableId", "com.figma.scopes", "com.figma.type" } }`;
  - groups are nested objects;
  - keys starting with `$` are never variables or groups.
  - **Figma's "Import mode" matches variables by token name and type.** The export must keep every name, nesting level and `$type` exactly as read.
- **Key paths** join group names with `.` (`Group.Sub.Variable`). DTCG names can't contain `.`, so this is unambiguous.
- **Only `$type: "string"` variables are translated.** All other variables pass through the export byte-for-byte.
- **Export changes only the `$value` of string variables.** Everything else is kept: key order, indentation (detected from the file), whether the file ends with a newline, `$extensions`, non-string variables.
- **Identity is the Figma variable ID.** A rename in Figma keeps the row's code key, link and translations.
- **Workspaces only.** Figma actions appear only when `session.workspace` is set.
- **Folder:** Figma files live in `design/figma/` by default, one subfolder per collection, e.g. `design/figma/ALL/ENG.tokens.json`. Files directly in `design/figma/` form the collection `""`.
- **Group names:**
  - `figma-<collection>`, where the collection is sanitized to `[A-Za-z0-9_-]` (anything else becomes `_`);
  - `figma` for the root collection.
- **Write-back skips Figma groups.** Unmapped Figma strings never go into the original TS files. Other exports (JSON, Paraglide, TS modules) include them, keyed by their Figma name.
- **The Figma export contains only Figma-origin variables** (including linked ones). It never creates new variables.
- **Exports are blocked while any conflict is open.** UI copy: `Resolve conflicts before exporting.`
- **Copy:**
  - row badge `No code key yet`;
  - row menu `Set code key…` / `Link to code key…`;
  - conflict labels `From Figma` / `From code` / `Original`;
  - Settings section `Figma`;
  - button `Import Figma files…`;
  - export option `Figma Variables (.tokens.json)`.
- **Mode suggestions:**

  | Mode name | Language |
  |---|---|
  | `EN`, `ENG`, `English` | `en` |
  | `TH`, `THA`, `Thai`, `ไทย` | `th` |
  | `JA`, `JP`, `JPN`, `Japanese` | `ja` |
  | `ZH`, `CN`, `Chinese` | `zh` |
  | `KO`, `KR`, `Korean` | `ko` |
  | `VI`, `Vietnamese` | `vi` |
  | `ID`, `Indonesian` | `id` |
  | `MS`, `Malay` | `ms` |
  | `FR`, `French` | `fr` |
  | `DE`, `German` | `de` |
  | `ES`, `Spanish` | `es` |

  - Matching ignores case.
  - Otherwise, a mode that is already a valid BCP-47 tag (e.g. `pt-BR`) maps to itself.
  - Otherwise there is no suggestion and the user picks.
- **Fixtures:** `src/test/fixtures/figma/ALL/ENG.tokens.json` and `TH.tokens.json` are byte-for-byte copies of the owner's example (`~/Downloads/ALL (1)/`). The example has no trailing newline and contains the real placeholder mismatch `{{neme}}` (EN) vs `{{name}}` (TH).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Before each commit: `pnpm test`, `pnpm exec tsc --noEmit`.

## Review Focus

1. **A Figma file that isn't valid JSON or has no mode name** (half-saved, or hand-edited). That file is skipped with a warning naming it. Its variables are neither changed nor marked removed, and the other files still sync. Pinned by `an unreadable mode file is skipped and its variables are not marked removed` (Task 4).
2. **A mode that isn't mapped to a language yet** (the designer added `JA` in Figma). Sync skips that file and reports `unmappedModes: ["JA"]`; the UI says so. Nothing is guessed silently. Pinned by `unmapped modes are reported, not guessed` (Task 4).
3. **Two Figma variables whose names differ only in group** (`Button.Save` and `Dialog.Save`). They become two rows. A Figma name equal to an existing code key in another group never collides. Pinned by `same leaf name in different groups gives two rows` (Task 4).
4. **Linking a Figma string whose texts differ from the code key's texts in some languages.** Equal languages merge silently; each differing language becomes one `"figma"` conflict; the export is blocked until they are resolved. Pinned by `link: differing languages become conflicts, equal ones merge` (Task 7).
5. **Export with a value containing characters JSON escapes** (`"`, `\`, newline, emoji, Thai). The written `$value` reads back equal, and the untouched variables stay byte-identical. Pinned by `special characters round-trip in $value` (Task 1).

**Interfaces:**
- Produces:

```ts
export interface FigmaVar { id: string; path: string[]; name: string; type: string; value: unknown } // name = path.join(".")
export type ParsedTokens = { ok: true; mode: string | null; vars: FigmaVar[] } | { ok: false; error: string };
export function parseTokens(text: string): ParsedTokens;
/** Rewrites $value of string variables whose id is in `values`; everything else byte-stable. */
export function rewriteTokens(text: string, values: ReadonlyMap<string, string>): string;
/** A new mode file from a template file: same structure, `mode` as modeName, string values from `values` (others kept). */
export function newModeFile(template: string, mode: string, values: ReadonlyMap<string, string>): string;

```

- `parseTokens`:
  - walks objects depth-first in key order;
  - a node with `$value` is a variable, which needs a string `$extensions["com.figma.variableId"]` (a variable without one is skipped);

  - `type` is `$type`, or `""` when it's missing;
  - it never throws.
- `rewriteTokens`:
  - parses the text;
  - sets `$value` for matching string variables;
  - re-serializes with the file's own indentation: the leading whitespace of the first indented line, or none for a one-line file;
  - keeps the presence or absence of a trailing `\n`;
  - returns the input unchanged when no value differs.

### Task 4: Sync from the Figma folder

**Files:**
- Create: `src/figma/sync.ts`
- Create: `src/figma/sync.test.ts`

**Interfaces:**
- Consumes: Task 1 `parseTokens`; Task 2 meta types and helpers; `session.insertKey`, `importCell`, `addNamespace`, `addLanguage`, `renameKey`, `setWorkspaceMeta`, `batch`, `value`.
- Produces:

```ts
export interface FigmaConflict extends Conflict { base?: MessageValue }   // origin "figma" is added by the store
export interface FigmaSyncResult {
  available: boolean;            // false: no meta.figma or folder missing; nothing changed
  conflicts: FigmaConflict[];
  added: KeyId[]; updated: KeyId[]; renamed: Array<{ from: KeyId; to: KeyId }>;
  removed: KeyId[];              // unmapped Figma rows newly marked removed-in-source
  unmappedModes: string[];       // sorted
  warnings: string[];            // unreadable files, by root-relative path
}
export function syncFromFigma(session: ProjectSession): Promise<FigmaSyncResult>;          // queued per session like syncFromSource
export function resolveFigmaConflict(session: ProjectSession, c: Conflict, pick: "mine" | "theirs"): void;
export async function readFigmaFolder(fs: Fs, root: string, dir: string): Promise<FigmaFolder>;
export interface FigmaFolder { files: Array<{ relPath: string; collection: string; text: string; parsed: ParsedTokens }> }
```

**Algorithm.** Mirror `src/workspace/sync.ts`; read it first.
1. Read every `*.tokens.json` under `dir`, at most one subfolder deep. The collection is the subfolder name, or `""` for the root.
2. A file that doesn't parse, or has no mode, gives a warning and is skipped. Its collection's variables are "unreadable": never marked removed, never changed.
3. A mode not in `meta.figma.modes` goes to `unmappedModes` and its file is skipped. It does **not** make the collection unreadable.
4. For each string variable `v` in each readable mode file `(collection, mode → locale)`:
   - **Row lookup:** `link = meta.figma.vars[v.id]`.
   - **New variable:** create a row `keyId(figmaGroupName(collection), v.name)`, adding the namespace if it's missing, and add the link `{ collection, name: v.name, row }`.
   - **Renamed in Figma** (`link.name !== v.name`): update `link.name`. If the row is still unmapped (in a Figma group), `renameKey` it to the new name and report it in `renamed`. A row with a code key keeps its key.
   - **Three-way per cell**, as in TS sync:
     - `base = baseline[v.id]?.[locale]`, `theirs = v.value`, `mine = session.value(link.row, locale)`;
     - theirs equal to base → skip;
     - mine equal to theirs → skip;
     - mine equal to base → take theirs (`importCell`; add the language if needed);
     - otherwise → a conflict `{ id: link.row, locale, mine, theirs, base }`, keeping mine.
5. **New baseline** = values read, except conflict cells (they keep the old baseline) and unreadable collections (their old rows stay).
6. **Removed:** a variable in `vars` whose collection was fully readable and that appears in none of its files.
   - If its row is an unmapped Figma row, add the row to `meta.removedInSource` (the existing "removed in source" UI handles it).
   - Either way, keep the link: it is cleared only when the user confirms the removal. Leave that to the existing removed-in-source flow, and record a `Ruling:`.
7. Write `meta.figma` (vars, baseline) and `removedInSource` with one `setWorkspaceMeta` call, only when they changed. All of it happens inside one `session.batch`.
- `resolveFigmaConflict`:
  - "theirs" imports the Figma value;
  - either way, that cell's baseline becomes the Figma value, so the next sync doesn't re-report it;
  - it removes the conflict from `session.conflicts`, as `resolveSyncConflict` does.

### Task 7: Code keys and links

**Files:**
- Create: `src/figma/link.ts`, `src/figma/link.test.ts`
- Create: `src/ui/FigmaKeyDialogs.tsx` (`SetCodeKeyDialog`, `LinkDialog`), `src/ui/FigmaKeyDialogs.test.tsx`
- Modify: `src/ui/RowMenu.tsx` (two items for Figma rows), and the row key cell in `src/ui/ListView.tsx` / `src/ui/TableView.tsx` (badge `No code key yet` when `isUnmappedFigmaRow`)

**Interfaces:**
- Produces in `src/figma/link.ts`:

```ts
export function suggestLinks(session: ProjectSession, row: KeyId, limit?: number): KeyId[]; // default 5
export function setCodeKey(session: ProjectSession, row: KeyId, to: KeyId): KeyId;          // moveKey + vars[*].row update
export function linkToKey(session: ProjectSession, row: KeyId, target: KeyId): FigmaConflict[];
```

- **`suggestLinks`:**
  - candidates are rows **not** in Figma groups;
  - score = similarity of the base-language texts (`1 − levenshtein / maxLen` on text trimmed, lowercased and with whitespace collapsed) plus 0.1 per other language whose text is exactly equal;
  - keep scores ≥ 0.6, highest first, ties broken by key order.
  - Write the small Levenshtein in the file; don't add a dependency.
- **`setCodeKey`:** the target group must be a non-Figma namespace. It moves the row and points every link whose `row` was the old id at the new id, in one batch.
- **`linkToKey(row, target)`:**
  - For each locale, with `f = value(row)` and `t = value(target)`: if `t` is undefined, import `f`; if they're equal, nothing; otherwise produce a conflict `{ id: target, locale, mine: t, theirs: f, base: baseline value }`.
  - Then point the link at `target` and `deleteKey(row)`, all in one batch.
  - The returned conflicts are added by the caller (the dialog) to the store with origin `"figma"`, using `patchSession`, appended to existing Figma conflicts.
